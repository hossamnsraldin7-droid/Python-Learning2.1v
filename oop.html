01. What is OOP

Object-Oriented Programming (OOP) is a programming paradigm that organizes code around objects. An object combines data (attributes) and behavior (methods) in one unit.

Python is an object-oriented language. Values such as integers, strings, lists, and functions are objects. Each object has a type, identity, and value.

The core idea:
A Class defines structure and behavior. An Object is a concrete instance created from that class.

Why use OOP?

  • Organization: Keep related data and behavior together.
  • Reusability: Reuse code through classes and inheritance.
  • Maintainability: Change components with less impact on others.
  • Scalability: Model larger systems as cooperating objects.

02. The Fundamentals

2.1 Class & Object

A Class is a blueprint. An Object is an instance created from that blueprint.

class Car:
    pass

car1 = Car()
car2 = Car()

print(type(car1))
print(car1 is car2)  # False: different objects

Both objects belong to the same class, but they have separate identities and states.

2.2 Attributes & Methods

Attributes store data. Methods define behavior and are functions defined inside a class.

class Car:
    def start(self):
        print("Engine started")

car = Car()
car.brand = "Toyota"       # Instance attribute
car.start()                # Method call
print(car.brand)
In normal class design, attributes are usually initialized in __init__() rather than added dynamically after object creation.

2.3 The Constructor — __init__()

__init__() is an initializer method. Python calls it automatically after an instance has been created, so you can set its initial state.

class Car:
    def __init__(self, brand, year):
        self.brand = brand
        self.year = year

car1 = Car("Toyota", 2022)
car2 = Car("BMW", 2024)

print(car1.brand)  # Toyota
print(car2.year)   # 2024
__init__() does not create the object itself. Object creation is handled by __new__(); __init__() initializes the new instance.

2.4 The self Keyword

self refers to the current instance. It lets a method access or modify that object's attributes and call its other methods.

class Student:
    def __init__(self, name, grade):
        self.name = name
        self.grade = grade

    def introduce(self):
        print(f"My name is {self.name}")
        print(f"My grade is {self.grade}")

student1 = Student("Ali", 90)
student2 = Student("Sara", 95)

student1.introduce()
student2.introduce()

When calling student1.introduce(), Python passes student1 as the first argument automatically. self is a naming convention, not a reserved keyword.

2.5 Instance Attributes vs Class Attributes

Instance attributes belong to one object. Class attributes are defined on the class and are shared unless shadowed by an instance attribute.

class Employee:
    company = "Tech Company"       # Class attribute

    def __init__(self, name):
        self.name = name           # Instance attribute

emp1 = Employee("Omar")
emp2 = Employee("Mona")

print(emp1.company)
print(emp2.company)
emp1.name = "Ahmed"  # Changes emp1 only

03. The Four Pillars of OOP

The four pillars are Encapsulation, Inheritance, Polymorphism, and Abstraction.

3.1 Encapsulation

Encapsulation means grouping data with the methods that manage it, and controlling how the object's internal state is accessed or changed.

StyleExampleMeaning in Python
Publicself.nameNormal attribute, accessible from anywhere.
Protected conventionself._balanceSingle underscore signals internal use by convention.
Name-mangledself.__balanceDouble leading underscores trigger name mangling.
Python does not enforce strict private access. A single underscore is a convention; double underscore performs name mangling, not absolute security.

Example 1 — Protect State with Methods

class BankAccount:
    def __init__(self, owner, balance):
        self.owner = owner
        self.__balance = balance

    def deposit(self, amount):
        if amount <= 0:
            raise ValueError("Amount must be positive")
        self.__balance += amount

    def get_balance(self):
        return self.__balance

account = BankAccount("Ali", 1000)
account.deposit(500)
print(account.get_balance())  # 1500

The balance is changed through a method that validates the amount, rather than arbitrary updates through the intended public interface.

Example 2 — Getters and Setters

class Product:
    def __init__(self, price):
        self.__price = price

    def get_price(self):
        return self.__price

    def set_price(self, value):
        if value < 0:
            raise ValueError("Price cannot be negative")
        self.__price = value

item = Product(100)
print(item.get_price())
item.set_price(150)
print(item.get_price())

Example 3 — Pythonic Encapsulation with @property

@property gives attribute-style access while keeping validation logic inside the class.

class Product:
    def __init__(self, price):
        self.price = price

    @property
    def price(self):
        return self.__price

    @price.setter
    def price(self, value):
        if value < 0:
            raise ValueError("Price cannot be negative")
        self.__price = value

item = Product(100)
print(item.price)   # Getter
item.price = 250    # Setter
print(item.price)
Use @property when an attribute needs controlled access but should remain natural to read and assign. Use ordinary methods for actions representing behavior.

3.2 Inheritance

Inheritance allows a child class to reuse and extend attributes or methods from a parent class. It can reduce duplication and support the DRY principle (Don't Repeat Yourself).

class Animal:
    def __init__(self, name):
        self.name = name

    def eat(self):
        print(f"{self.name} is eating")


class Dog(Animal):
    def bark(self):
        print(f"{self.name} says Woof!")


dog = Dog("Max")
dog.eat()   # Inherited method
dog.bark()  # Dog's own method

Method Overriding

A child class can provide its own implementation of an inherited method. This is Method Overriding.

class Animal:
    def speak(self):
        print("Some generic sound")

class Dog(Animal):
    def speak(self):
        print("Woof!")

dog = Dog()
dog.speak()  # Woof!

Using super()

super() gives access to the next implementation in the Method Resolution Order (MRO). It is commonly used to extend a parent's initialization or behavior.

class Person:
    def __init__(self, name):
        self.name = name

class Student(Person):
    def __init__(self, name, student_id):
        super().__init__(name)
        self.student_id = student_id

student = Student("Mona", 2025001)
print(student.name)
print(student.student_id)

Types of Inheritance

TypeDescription
SingleOne child inherits from one parent.
MultipleOne child inherits from multiple parents.
MultilevelA class inherits from a class that already inherits from another class.
HierarchicalMultiple child classes inherit from the same parent.
HybridA combination of inheritance patterns.

Multiple Inheritance Example

class Camera:
    def take_photo(self):
        print("Photo captured")

class Phone:
    def make_call(self):
        print("Calling...")

class SmartPhone(Camera, Phone):
    pass

device = SmartPhone()
device.take_photo()
device.make_call()
Python resolves inherited methods using the Method Resolution Order (MRO). Inspect it with SmartPhone.mro(). Use multiple inheritance carefully.

3.3 Polymorphism

Polymorphism means "many forms". Different objects can respond to the same method call in different ways.

Example 1 — Same Method, Different Classes

class Dog:
    def speak(self):
        return "Woof!"

class Cat:
    def speak(self):
        return "Meow!"

animals = [Dog(), Cat()]
for animal in animals:
    print(animal.speak())

The loop does not need to know the exact class. It only relies on each object providing a compatible speak() method.

Example 2 — Polymorphism through Inheritance

class Shape:
    def area(self):
        raise NotImplementedError

class Rectangle(Shape):
    def __init__(self, width, height):
        self.width = width
        self.height = height

    def area(self):
        return self.width * self.height

class Circle(Shape):
    def __init__(self, radius):
        self.radius = radius

    def area(self):
        return 3.14159 * self.radius ** 2

shapes = [Rectangle(4, 5), Circle(3)]
for shape in shapes:
    print(shape.area())
Python also supports duck typing: an object can be used based on the methods it provides, without inheriting from a specific parent class.

3.4 Abstraction

Abstraction exposes the essential interface while hiding implementation details. Python provides the abc module for abstract base classes.

from abc import ABC, abstractmethod

class Payment(ABC):
    @abstractmethod
    def pay(self, amount):
        pass

class CreditCardPayment(Payment):
    def pay(self, amount):
        print(f"Paid {amount} using credit card")

class CashPayment(Payment):
    def pay(self, amount):
        print(f"Paid {amount} in cash")

payment = CreditCardPayment()
payment.pay(250)

A class with unimplemented abstract methods cannot be instantiated. A concrete subclass must implement the required abstract methods.

Common mistake: Importing ABC alone does not make a method abstract. Decorate the required method with @abstractmethod.

04. Advanced Python OOP

4.1 Magic / Dunder Methods

Dunder means "double underscore". These special methods let custom objects work with built-in operations such as str(), len(), and operators.

MethodPurpose
__init__Initialize a new instance.
__str__Human-readable representation, used by str() and print().
__repr__Developer-oriented representation, used by repr().
__len__Defines the result of len(obj).
__add__Defines behavior for the + operator.

Example 1 — __str__ and __repr__

class Book:
    def __init__(self, title, author):
        self.title = title
        self.author = author

    def __str__(self):
        return f"{self.title} by {self.author}"

    def __repr__(self):
        return f"Book({self.title!r}, {self.author!r})"

book = Book("Clean Code", "Robert C. Martin")
print(str(book))
print(repr(book))

Example 2 — __len__

class Team:
    def __init__(self, members):
        self.members = members

    def __len__(self):
        return len(self.members)

team = Team(["Ali", "Mona", "Omar"])
print(len(team))  # 3

Example 3 — __add__

class Vector:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    def __add__(self, other):
        if not isinstance(other, Vector):
            return NotImplemented
        return Vector(self.x + other.x, self.y + other.y)

    def __repr__(self):
        return f"Vector({self.x}, {self.y})"

v1 = Vector(2, 3)
v2 = Vector(4, 5)
print(v1 + v2)  # Vector(6, 8)
Return NotImplemented when an operator does not support the other operand's type. Python can then try a reflected operation or raise an appropriate error.

4.2 Instance Methods, Class Methods & Static Methods

Method typeFirst parameterTypical use
Instance methodselfRead or modify a particular object's state.
Class methodclsWork with class-level state or alternative constructors.
Static methodNone automaticallyRelated utility needing neither instance nor class state.
class Employee:
    company = "Tech Company"

    def __init__(self, name, salary):
        self.name = name
        self.salary = salary

    # Instance method
    def show_info(self):
        return f"{self.name}: {self.salary}"

    # Class method
    @classmethod
    def change_company(cls, new_name):
        cls.company = new_name

    # Static method
    @staticmethod
    def is_valid_salary(salary):
        return salary >= 0

emp = Employee("Ali", 5000)
print(emp.show_info())
Employee.change_company("New Tech")
print(Employee.company)
print(Employee.is_valid_salary(5000))

Alternative Constructor with @classmethod

class User:
    def __init__(self, name, age):
        self.name = name
        self.age = age

    @classmethod
    def from_string(cls, data):
        name, age = data.split(",")
        return cls(name, int(age))

user = User.from_string("Mona,21")
print(user.name)
print(user.age)

4.3 Properties — @property

Properties allow a method to be accessed like an attribute. They are useful for validation, computed values, and maintaining a stable public interface.

class Circle:
    def __init__(self, radius):
        self.radius = radius

    @property
    def radius(self):
        return self.__radius

    @radius.setter
    def radius(self, value):
        if value <= 0:
            raise ValueError("Radius must be positive")
        self.__radius = value

    @property
    def area(self):
        return 3.14159 * self.radius ** 2

circle = Circle(5)
print(circle.radius)
print(circle.area)
circle.radius = 7
print(circle.area)

area has no setter, so it is a read-only computed property.

4.4 Data Classes — @dataclass

The dataclasses module reduces boilerplate for classes mainly used to store data. @dataclass can generate methods such as __init__, __repr__, and __eq__.

from dataclasses import dataclass

@dataclass
class Student:
    name: str
    age: int
    grade: float

student1 = Student("Ali", 20, 3.5)
student2 = Student("Ali", 20, 3.5)

print(student1)
print(student1 == student2)  # True

Mutable Defaults with field()

Use field(default_factory=...) when every object needs its own mutable default value, such as a list or dictionary.

from dataclasses import dataclass, field

@dataclass
class Course:
    name: str
    students: list = field(default_factory=list)

course1 = Course("Python")
course2 = Course("C++")
course1.students.append("Omar")

print(course1.students)  # ['Omar']
print(course2.students)  # []

05. Design & Best Practices

5.1 Composition over Inheritance

Inheritance represents an is-a relationship. Composition represents a has-a relationship: one object contains or uses another object. Prefer composition when objects are collaborators rather than specialized versions of the same concept.

class Engine:
    def start(self):
        print("Engine started")

class Car:
    def __init__(self):
        self.engine = Engine()  # Car has an Engine

    def start(self):
        self.engine.start()

car = Car()
car.start()

5.2 Single Responsibility Principle (SRP)

A class should have one clear responsibility and one main reason to change. Avoid classes that handle unrelated tasks.

class Invoice:
    def __init__(self, total):
        self.total = total

class InvoicePrinter:
    def print_invoice(self, invoice):
        print(f"Invoice total: {invoice.total}")

invoice = Invoice(500)
printer = InvoicePrinter()
printer.print_invoice(invoice)

5.3 Keep Interfaces Small

Expose only the operations that users of a class need. Avoid large classes with many unrelated methods.

5.4 Clear Names and Type Hints

class ShoppingCart:
    def __init__(self) -> None:
        self.items: list[str] = []

    def add_item(self, item: str) -> None:
        self.items.append(item)

    def item_count(self) -> int:
        return len(self.items)

5.5 Avoid Unnecessary Inheritance

  • Do not create a parent class only to share one tiny piece of code.
  • Use inheritance when the child truly represents a specialized form of the parent.
  • Use composition when a class needs another object's functionality.
  • Keep methods focused and avoid hidden side effects.

5.6 Quick Design Guide

QuestionPossible design choice
Do several objects share a common contract?Consider an abstract base class or a protocol.
Is one object a specialized type of another?Consider inheritance.
Does one object use another as a component?Consider composition.
Does an attribute need validation?Consider @property or an explicit method.
Is the class mainly a data container?Consider @dataclass.
